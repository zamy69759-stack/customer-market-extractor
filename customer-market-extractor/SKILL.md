# 客户与市场知识萃取

在本 Skill 目录使用 `python run.py` 执行确定性的发现、解析、增量索引与卡片骨架生成；复杂的跨来源关联、意图判断和故事还原由 Codex 在证据范围内完成。

## 开始前

1. 读取 `config.json`。首次使用必须让用户亲自提供原始语料库、企业知识库和工具工作目录，不得通过目录名称、邻近路径或扫描结果代替用户选择。缺失或路径不可用时，运行 `python run.py configure`；配置完成前不得扫描语料。
2. 原始语料默认只读。仅写入配置的工作目录，以及知识库根目录下既有或经用户确认创建的 `客户与市场`。
3. 图片 OCR、音频转写或任何云服务调用均为可选能力；调用第三方前说明服务和传输范围并取得明确同意。不得假装读过只有文件名的附件。

## 工作流

1. 用 `scan <相对路径>` 发现文件，计算 SHA-256，并生成逐文件解析报告。只处理 manifest 中新增或变化的文件。
2. 按客户、项目、线程、产品、时间和事件标识关联证据。同名客户或不确定关联必须分开并进入人工复核。
3. 基于证据还原背景、问题、双方沟通、方案、执行、反馈和结果。未出现的环节写“原始资料未提供”。批准图纸不等于收到 PO；考虑不等于成交。
4. 生成或增量更新一张有独立价值的卡。保留人工编辑和审核状态；冲突列入复核报告，不自动覆盖。
5. 更新 `客户与市场/INDEX.md` 与工作目录 `manifest.json`，并运行 `validate` 检查命名、YAML、12 节、证据定位和相对链接。

详细格式与事实边界见 [references/knowledge-card-spec.md](references/knowledge-card-spec.md)。解析器能力与降级方式见 [references/input-support.md](references/input-support.md)。

## 安全边界

- 关键事实必须对应来源文件与页码、行号、时间戳、邮件主题或截图位置。
- 推断显式标注；单个客户观点只能作为个案，不能外推市场趋势。
- 客户姓名、邮箱、价格和项目隐私默认内部使用，`公开发布许可: 待确认`。
- LinkedIn 仅输出真实素材、选题和待核实项，不自动生成或发布帖子。
- 音频仅在用户明确要求、确认数据处理且本机具备能力时转写。

## 常用命令

```bash
python run.py status
python run.py scan "客户日常沟通/Bayside"
python run.py validate
python run.py configure
```
